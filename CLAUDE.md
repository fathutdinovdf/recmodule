# Модуль управления рекомендациями — правила работы над проектом

## Что это

Макет специализированного модуля КИС «Виртуальный расходомер» по договору
ООО «ЛУКОЙЛ-Западная Сибирь» (Заказчик) ↔ ООО «АКЭ» (Исполнитель) — экспертное
сопровождение механизированного фонда скважин, услуги с 01.07.2026 по 30.12.2027.

Исполнитель выдаёт рекомендации по скважинам, Заказчик принимает по ним решения
и выполняет мероприятия, эффект подтверждается в 90-суточном окне. Модуль
автоматизирует то, что сейчас ведётся в трёх Excel-формах.

Сейчас в работе **прототип на статике**: HTML/CSS/JS без сборщика, открывается
двойным кликом по файлу. Перенос в React пойдёт потом один в один — разметка и
классы от фреймворка не зависят.

## Что читать перед работой

Порядок важен:

1. **`Дизайн модуля — принятые решения.md`** — источник истины. Больше 70
   пронумерованных решений. Читать целиком: часть решений отменена более
   поздними, отмены помечены явно. Если делаешь что-то, противоречащее решению, —
   это ошибка, а не свобода творчества.
2. **`Расхождения с договором.md`** — 17 расхождений макета с договором,
   15 пробелов, 12 позиций сверх договора. Проверь, не касается ли твоя задача
   чего-то оттуда.
3. **`Вопросы к обсуждению.md`** — открытые развилки. Если упёрся в один из этих
   вопросов, не решай его молча: сделай по умолчанию и вынеси в отчёт.
4. **`ВМАП — визуальный язык.md`** — композиция, плотность, паттерны.
5. **`tokens.css`** — переменные обеих тем.
6. **`макет/index.html` + `макет/app.js` + `макет/registry.css`** — реестр,
   оболочка приложения и все базовые классы.
7. **`макет/card.html` + `макет/card.js` + `макет/card.css`** — карточка,
   эталон стиля кода и вёрстки форм.
8. **`макет/wizard.*`** — мастер регистрации, там же компонент выпадающего списка.
9. **`макет/data.js`** — справочники и 180 тестовых записей.

## Жёсткие правила

- **Статика.** Без сборщика, без npm, без внешних зависимостей и CDN. Файл
  открывается двойным кликом.
- **Только токены.** Все цвета, отступы, радиусы, шрифты — через переменные
  `tokens.css`. Никаких `#fff`, `rgba(...)`, магических пикселей в цветах.
  Отступление от токенов допустимо, если так объективно лучше (решение 71), —
  но с комментарием в коде, объясняющим почему.
- **Светлая тема основная**, тёмная работает тем же слоем токенов через
  `data-theme="dark"`. Учти: в тёмной теме `--text-primary`, `--text-tertiary`
  и `--text-quaternary` сломаны на уровне токенов (решение 68) — это известно,
  чинить в одностороннем порядке нельзя.
- **«Сейчас» зафиксировано:** `NOW = new Date('2026-08-05T08:40:00')` в `data.js`.
  Никогда не бери реальное текущее время — макет разъедется сам с собой.
- **Интерфейс по-русски.** Буква «ё» пишется. Тире длинное «—». Даты
  ДД.ММ.ГГГГ, время ЧЧ:ММ.
- **`[hidden] { display: none !important; }`** в `registry.css` — правило
  намеренное: любой класс с `display` молча переопределяет атрибут `hidden`.
  Не отменяй его.

## Стиль кода

Комментарии объясняют **почему** так сделано, а не что делает строка. Через
месяц никто не вспомнит, какой случай породил правило, если не написать. Смотри
`data.js` и `card.js` — держи ровно этот стиль, он тут единственная документация
неочевидных решений наравне с документом решений.

Плохо: `// фильтруем массив`
Хорошо: `/* Черновики в аналоги не попадают: у черновика нет номера, и в реестре его видит только автор. */`

## Проверка — обязательна

1. `node --check` по каждому изменённому `.js`.
2. Рендер **локальным headless Chrome** и просмотр скриншота глазами:
   ```
   "/c/Program Files/Google/Chrome/Application/chrome.exe" --headless --disable-gpu \
     --virtual-time-budget=2500 --window-size=1600,1000 --screenshot=ПУТЬ.png "file:///C:/..."
   ```
   Путь с кириллицей percent-энкодить. **Встроенное превью не использовать** —
   оно отдаёт статический снимок и не выполняет скрипты.
3. `--dump-dom` вместо скриншота, когда надо проверить, что скрипт не упал:
   в `index.html` таблица и в `card.html` вся карточка собираются скриптом,
   и на скриншоте пустая страница выглядит просто пустой страницей.
4. **Состояния по клику** (модалки, меню, выпадающие списки) снимаются так:
   временная копия страницы `_probe.html` с инжектом
   `<script>document.querySelector('СЕЛЕКТОР').click()</script>` после подключения
   скрипта; отрендерить, посмотреть, копию удалить. Скриншот сам ничего не нажимает.
5. **Числа на экране сверять с данными** независимым node-скриптом: `data.js`
   грузится как `new Function(код + '; return {DATA};')()`. Разошлось — врёт
   логика отбора, а не арифметика в голове.

## Что нельзя ломать

Общие файлы правит только основная сессия: `макет/data.js`, `макет/app.js`,
`макет/card.js`, `макет/index.html`, `макет/card.html`, `макет/registry.css`,
`макет/card.css`, `tokens.css`, и оба документа — решений и вопросов.

Если работаешь над отдельным экраном — создавай **свои** файлы
(`экран.html` / `экран.js` / `экран.css`), оболочку приложения копируй из
`index.html` в свой html. Из общих файлов только читай: подключай `data.js`
скриптом и бери оттуда `DATA`, справочники, `STATUS_TONE`, `SLA_VISIBLE_STATUSES`,
`NOW`, функции рабочего окна.

Причина простая: над проектом идут параллельные сессии, и правки в общие файлы
из двух мест одновременно превращаются в конфликт, который разбирать дороже,
чем сделать работу.

## Ключевые решения, которые чаще всего нарушают по незнанию

- **Статусов десять,** а не двенадцать. «Реализуется», «Реализовано» и
  «Частично реализовано» статусами не являются: полнота реализации — поле.
- **Факт реализации определяет Исполнитель** по телеметрии, не Заказчик.
  Фиксация сразу открывает окно эффекта.
- **Поля «источник рекомендации» нет.** Упразднено: рекомендации выдаёт только
  Исполнитель.
- **ЦИТС в объектной модели нет.** Иерархия: ДО → ТПП → ЦДНГ → месторождение →
  куст → скважина, причём «месторождение» в ВМАП — пара месторождение × цех.
- **Приоритет и контроль ответа** показываются только на статусах
  `registered`, `sent`, `review` — константа `SLA_VISIBLE_STATUSES` в `data.js`.
- **Кружок статуса кодирует две вещи:** цвет — чья сторона держит процесс,
  заливка — доведён ли шаг до конца. Таблица `STATUS_TONE`. Своей цветовой
  семантики не выдумывать.
- **Нормативы 4/8/24 — не из договора,** а из Формы 2. Оставлены сознательно,
  но идут в протокол согласования форм (решение 64).

## Git

Каждая задача — своя ветка и свой worktree в `../wt/<имя>`. Работа коммитится
в своей ветке; **сливает в master основная сессия**, не сами агенты. Сообщения
коммитов по-русски, по существу: что изменилось и почему, а не «правки».

## Отчёт о работе

В финальном ответе: что сделано, какие решения принял сам и почему (особенно там,
где документ решений молчал), что осталось спорным, пути к скриншотам. Нашёл
противоречие в документе решений или расхождение с договором — вынеси отдельным
пунктом, не молчи.
