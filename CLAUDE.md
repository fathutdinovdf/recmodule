# Модуль управления рекомендациями — правила работы над проектом

## Что это

Специализированный модуль КИС «Виртуальный расходомер» по договору
ООО «ЛУКОЙЛ-Западная Сибирь» (Заказчик) ↔ ООО «АКЭ» (Исполнитель) — экспертное
сопровождение механизированного фонда скважин, услуги с 01.07.2026 по 30.12.2027.

Исполнитель выдаёт рекомендации по скважинам, Заказчик принимает по ним решения
и выполняет мероприятия, эффект подтверждается в 90-суточном окне. Модуль
автоматизирует то, что сейчас ведётся в трёх Excel-формах.

## Где что лежит: две половины проекта

Это главное, что нужно понять до первой правки.

**`app/` — то, над чем идёт работа.** Next.js 15 + React 19 + TypeScript,
PostgreSQL 15.5 в Docker, реальные данные с дев-стенда ВМАП. Здесь npm, сборщик
и серверные операции — всё, что раньше было запрещено.

**`макет/` — замороженный эталон вёрстки.** Статический HTML/CSS/JS без
сборщика, девять экранов, выверенный визуальный язык. Оттуда переносятся
разметка и CSS один в один. **Только читать.** Экран, сделанный в `app/`, в
макете не правится и не удаляется: макет остаётся образцом для ещё не
перенесённых экранов и историей принятых визуальных решений.

Если задача звучит как «сделать экран» — почти всегда это перенос экрана из
`макет/` в `app/`, а не рисование с нуля.

## Что читать перед работой

Порядок важен:

1. **`app/BRIEF.md`** — состояние работы: что сделано, что дальше, какие
   решения приняты по архитектуре приложения и почему. Читать первым.
2. **`Дизайн модуля — принятые решения.md`** — источник истины по предметной
   части и интерфейсу, 95+ пронумерованных решений. Часть решений отменена
   более поздними, отмены помечены явно. Если делаешь что-то, противоречащее
   решению, — это ошибка, а не свобода творчества.
3. **`Расхождения с договором.md`** — расхождения макета с договором, пробелы и
   позиции сверх договора. Проверь, не касается ли твоя задача чего-то оттуда.
4. **`Вопросы к обсуждению.md`** — открытые развилки. Если упёрся в один из
   этих вопросов, не решай его молча: сделай по умолчанию и вынеси в отчёт.
5. **`ВМАП — визуальный язык.md`** — композиция, плотность, паттерны.
6. **`app/src/app/tokens.css`** и **`registry.css`** — переменные обеих тем и
   все базовые классы; это копии из макета, правятся вместе с ним.
7. **Соответствующий экран в `макет/`** — разметка и CSS того, что переносишь.

## Запуск

```
cd app
npm run db:up      # PostgreSQL в Docker (нужен запущенный Docker Desktop)
npm run dev        # актуализирует демо-данные и поднимает сервер на :3100
```

Прочее: `npm run db:seed` — пересоздать демо, `npm run db:rebase` — пересчитать
базовые значения демо по настоящим замерам ВМАП (нужен доступ на стенд),
`npm run db:refresh` — сдвинуть даты демо к сегодня, `npm run db:load-economy` —
перезалить ставки.

Миграции в `app/db/migrations/` накатывает `npm run db:migrate`: применяет
непринятые файлы по возрастанию имени, каждый в своей транзакции, и пишет
принятое в `rec.schema_migrations`. Применённый файл больше не трогается,
изменённый после применения — называется вслух. На базе, где схема уже есть, а
журнала ещё нет, сначала `npm run db:migrate -- --baseline`: он отметит файлы
принятыми, ничего не выполняя. Отдельный файл, накатанный руками, отмечается
`-- --mark 010_daily_fact_log.sql`.

**Номер миграции берётся с оглядкой на чужие ветки.** Параллельные сессии
нумеруют от общего master и дважды занимали один номер. Перед тем как завести
файл: `git ls-tree --name-only <ветка> app/db/migrations/` по неслитым веткам,
и брать следующий свободный по всем.

Пароли и адреса — в `app/.env.local` (не в гите, значения по умолчанию
продублированы в скриптах).

## Жёсткие правила

- **Домен без Next.** Предметная логика — расчёт эффекта, агрегация замеров,
  рабочие часы, базовые значения — живёт в `app/src/domain/` без единого импорта
  из Next и из БД. Причина: фронт ВМАП — React 18 SPA на Vite; при встраивании
  серверная половина Next не переедет, а домен переживёт смену обвязки.
- **Стенд ВМАП только на чтение.** `vmapQuery` отклоняет всё, кроме SELECT.
  Не обходить: это чужая база, и она не наша, чтобы в ней ошибаться.
- **Только токены.** Все цвета, отступы, радиусы, шрифты — через переменные
  `tokens.css`. Никаких `#fff`, `rgba(...)`, магических пикселей в цветах.
  Отступление допустимо, если так объективно лучше (решение 71), — но с
  комментарием в коде, объясняющим почему.
- **Светлая тема основная**, тёмная работает тем же слоем токенов через
  `data-theme="dark"`. В тёмной теме `--text-primary`, `--text-tertiary` и
  `--text-quaternary` сломаны на уровне токенов (решение 68) — это известно,
  чинить в одностороннем порядке нельзя.
- **Настоящее время, но демо не протухает.** В приложении время настоящее
  (в отличие от макета, где `NOW` зафиксировано). Свежесть демо-набора держит
  сдвиг дат: `refresh-demo` двигает весь набор целиком на целое число суток.
  Записи без `is_demo` не двигаются — их даты правда.
- **Интерфейс по-русски.** Буква «ё» пишется. Тире длинное «—». Даты
  ДД.ММ.ГГГГ, время ЧЧ:ММ. Имена в коде тоже могут быть русскими там, где так
  понятнее, — смотри `actions.ts`.
- **`[hidden] { display: none !important; }`** в `registry.css` — правило
  намеренное: любой класс с `display` молча переопределяет атрибут `hidden`.
  Не отменяй его.
- **Tailwind preflight выключен.** Переход на shadcn идёт поэлементно поверх
  существующей вёрстки; сброс стилей снёс бы макет целиком.

## Стиль кода

Комментарии объясняют **почему** так сделано, а не что делает строка. Через
месяц никто не вспомнит, какой случай породил правило, если не написать. Эталон —
`app/src/app/rec/[id]/actions.ts`, `app/src/domain/measurements.ts`,
`app/db/migrations/001_init.sql`: комментарии там — единственная документация
неочевидных решений наравне с документом решений.

Плохо: `// фильтруем массив`
Хорошо: `/* Черновики в аналоги не попадают: у черновика нет номера, и в реестре его видит только автор. */`

## Дизайн — своя работа, а не побочный результат

Экран не «переносится» и не «собирается из блоков»: он продумывается. До
первой строки разметки должно быть решено, на какой вопрос экран отвечает,
что человек делает на нём первым, какие у него состояния — пустое, занятое,
отказ — и почему выбрана эта композиция, а не таблица со всплывающим окном.
Решения этого уровня пишутся в комментарии файла: через месяц никто не
вспомнит, почему список слева, а не строки в таблице.

**Компоненты берутся готовые, а не пишутся заново.** Порядок поиска:

1. `app/src/components/ui` — то, что уже стоит в проекте (`Select`, `Switch`,
   `ActionDialog`, `Combobox`, `badge`, `item`, `empty`, `avatar`…). Сначала
   ищем здесь: половина «нужного нового» уже лежит рядом.
2. `app/src/components/animate-ui` — движение: подсветка выбора, счётчики,
   сегментированные переключатели.
3. Реестры, прописанные в `app/components.json`, — shadcn, `@animate-ui`,
   `@kibo-ui`:

```
npx shadcn@latest add switch
npx shadcn@latest add @animate-ui/radix-tabs
npx shadcn@latest add @kibo-ui/kanban
```

Своё пишется только когда в реестрах этого нет, и тогда — в манере
существующих: поведение и доступность от Radix, движение пружиной `motion`,
цвета и отступы токенами (эталон — `components/ui/Checkbox.tsx`,
`components/ui/Switch.tsx`).

## Проверка

**Логику проверяет пользователь, интерфейс — ты сам.** Разница в том, что
видно на экране.

Для любой правки:

```
npx tsc --noEmit
```

**Если менялся вид** — новый экран, новая разметка, стили, состояния, —
недостаточно. Снимок обязателен, и смотреть его должен ты, а не пользователь:

```
node scripts/render.mjs /users C:\путь\снимок.png
```

Путь абсолютный, dev-сервер поднят, роль задаётся `DEMO_USER` при его запуске
(`DEMO_USER=admin npx next dev -p 3199`). Смотреть на снимок и спрашивать себя:
не съехало ли выравнивание, видны ли границы в **светлой** теме (она основная,
и `--border-divider-light` в ней почти невидим), не жмётся ли текст, что
происходит при пустых данных. Найденное — чинить до того, как показывать
работу. «Верстка написана» и «экран выглядит правильно» — разные состояния, и
второе проверяется только глазами.

Чего по-прежнему не нужно без просьбы: прогон обеих ролей, отправка форм из
консоли, сверка чисел запросами к базе.

Среду оставлять рабочей: **добавил новый файл — снеси `.next`** и подними
сервер заново (`npm run dev:only`), иначе он отдаёт
`__webpack_modules__[moduleId] is not a function` на странице, которая
компилировалась до появления модуля.

База под рукой — `docker exec recmodule-db psql -U recmodule -d recmodule`.

## Ключевые решения, которые чаще всего нарушают по незнанию

- **Статусов десять,** а не двенадцать. «Реализуется», «Реализовано» и
  «Частично реализовано» статусами не являются: полнота реализации — поле.
- **Факт реализации определяет Исполнитель** по телеметрии, не Заказчик.
  Фиксация сразу открывает окно эффекта.
- **Поля «источник рекомендации» нет.** Упразднено: рекомендации выдаёт только
  Исполнитель.
- **ЦИТС в объектной модели нет.** Иерархия: ДО → ТПП → ЦДНГ → месторождение →
  куст → скважина, причём «месторождение» в ВМАП — пара месторождение × цех.
- **Приоритет и контроль ответа** показываются только на статусах
  `registered`, `sent`, `review`.
- **Кружок статуса кодирует две вещи:** цвет — чья сторона держит процесс,
  заливка — доведён ли шаг до конца. Таблица `rec.statuses` (миграция
  `004_status_tone`). Своей цветовой семантики не выдумывать.
- **Нормативы 4/8/24 — не из договора,** а из Формы 2. Оставлены сознательно,
  но идут в протокол согласования форм (решение 64).
- **Норматив ответа при уточнении не начинается заново,** а продолжается с
  остатка после повторной передачи — редакция договора от 30.07.2026.

## Грабли, на которые уже наступали

Полный список — в `app/BRIEF.md`, раздел «Грабли». Самое частое:

- **`app.css` грузится после `registry.css` и перебивает макет.** В нём не
  должно быть `.tbl`, `.panel`, `.btn`, `.field` — только собственные классы.
- **Любой экспорт из модуля с `'use client'` приезжает на сервер клиентской
  ссылкой, а не значением.** Константы, нужные серверу, держать в отдельном
  файле без `'use client'` (так разделены `tabs-def.ts` и `tabs.tsx`).
- **Замеры ВМАП не фильтровать по `DeleteDate IS NULL`** — вся история именно с
  проставленным `DeleteDate`, живых записей меньше процента.
- **Ноль в плотности нефти или воды на стенде** — незаполненное поле, а не
  лёгкая нефть.

## Git

Каждая задача — своя ветка и свой worktree в `../wt/<имя>`. Работа коммитится
в своей ветке; **сливает в master основная сессия**, не сами агенты. Сообщения
коммитов по-русски, по существу: что изменилось и почему, а не «правки».

Общие файлы правит только основная сессия: `app/src/app/registry.css`,
`tokens.css`, `app/src/app/layout.tsx`, `app/src/components/AppShell.tsx`,
`app/db/migrations/*`, `app/BRIEF.md` и оба документа — решений и вопросов.
Причина: над проектом идут параллельные сессии, и правки в общие файлы из двух
мест одновременно превращаются в конфликт, который разбирать дороже, чем
сделать работу.

## Отчёт о работе

В финальном ответе: что сделано, какие решения принял сам и почему (особенно
там, где документ решений молчал), что осталось спорным, пути к скриншотам.
Нашёл противоречие в документе решений или расхождение с договором — вынеси
отдельным пунктом, не молчи.

Сделал заметный кусок — допиши `app/BRIEF.md`: он единственное место, откуда
новая сессия узнаёт состояние работы.
